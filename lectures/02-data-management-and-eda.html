Data Management & Exploratory Data Analysis

How to keep a dataset trustworthy as it moves through its lifecycle, the documentation that makes it usable by someone else, the legal and ethical limits on working with it, and the first statistical and visual tools for exploring it.

The data management cycle

Data management is the set of processes used to collect, store, organise, maintain, protect and use data effectively. It aims to keep data:

  • Accurate — values correctly represent the real-world situation.
  • Complete — all required information is present, without missing values.
  • Consistent — the same definitions, formats and rules are used throughout.
  • Accessible — authorised users can locate and understand it.
  • Secure — protected from unauthorised access.
  • Documented — its meaning, origin and transformations are recorded.

The lifecycle itself runs: Collection → Storage → Cleaning → Transformation → Analysis → Reporting → Archiving/Deletion, typically looping back rather than running once in a straight line.

Data consistency

Data consistency means values, formats, definitions and relationships stay logically compatible throughout a dataset. Achieving it means using validation rules, naming conventions and controlled categories, documenting changes, and checking datasets before combining them.

Common consistency problems
  • Different date formats: 21/09/2026, 2026-09-21, Sep 21, 2026
  • Different units: kilograms vs. pounds, euro vs. dollars
  • Inconsistent category labels: Ireland, IRE, Republic of Ireland
  • Spelling differences: Dublin, DUBLIN, Dubln
  • Duplicate records, and different definitions for the same variable

Main principle: consistent data make comparison, aggregation and analysis more reliable.

Documentation and the data dictionary

A data dictionary documents the structure, meaning and permitted values of variables within a dataset. It interprets variables consistently, prevents incorrect assumptions, identifies data types and permitted ranges, makes datasets easier to share, and supports reproducibility — it should be updated whenever the dataset structure changes.

Data quality and preprocessing

Real-world datasets are never ready for analysis as-is. Common data-quality problems:

  • Missing values
  • Duplicate observations
  • Incorrect data types
  • Invalid values
  • Inconsistent formatting
  • Typographical errors
  • Extreme or unusual observations
  • Inconsistent categories

A typical preprocessing workflow:

  1. Inspect the dataset — rows, columns, variable types, dimensions.
  2. Identify problems — missing, invalid or inconsistent values.
  3. Clean — correct errors, remove inappropriate duplicates, standardise formats.
  4. Transform — create useful variables or change representations.
  5. Validate — confirm cleaning hasn't introduced new problems.
  6. Document — record what was changed and why.

Data cleaning should not simply remove inconvenient observations — every decision should have a defensible reason.

Legal, ethical and regulatory constraints

Working with data carries responsibilities beyond the technical analysis. For organisations operating in Ireland and the EU, personal-data processing is governed principally by the General Data Protection Regulation (GDPR) and Ireland's Data Protection Act 2018. GDPR's principles:

  • Lawfulness, fairness and transparency
  • Purpose limitation
  • Data minimisation
  • Accuracy
  • Storage limitation
  • Integrity and confidentiality
  • Accountability

Beyond the legal minimum, analysts should also weigh:

  • Privacy and confidentiality
  • Bias and discrimination
  • Transparency and representativeness
  • Potential harm and responsible interpretation

Statistical properties of data

Descriptive statistics summarise the important characteristics of a dataset:

  • Central tendency — mean, median, mode
  • Spread — range, variance, standard deviation, interquartile range (IQR)
  • Distribution — shape, symmetry, skewness, outliers, min/max, quartiles
Example

A large difference between the mean and the median can indicate a skewed distribution, or the influence of extreme observations.

Univariate analysis

Univariate analysis examines one variable at a time.

  • Numerical example — Student Age: What's the average/median age? Youngest/oldest? How widely are ages spread? Are there unusual values?
    Useful techniques: mean, median, standard deviation, min/max, quartiles, histogram, box plot.
  • Categorical example — Course: Which course has the most students? How many per category? What percentage per category?
    Useful techniques: frequency tables, percentages, mode, bar charts.

Bivariate and multivariate analysis

Bivariate analysis examines the relationship between two variables:

  • Numerical + Numerical — e.g. study hours vs. exam results → scatter plot, correlation.
  • Categorical + Numerical — e.g. course vs. average exam result → grouped statistics, box plots.
  • Categorical + Categorical — e.g. programme vs. employment status → cross-tabulation, grouped bar chart.

Multivariate analysis examines three or more variables simultaneously — e.g. Exam Result = Study Hours + Attendance + Previous Result + Programme — using correlation matrices, scatterplot matrices, grouped analysis, multiple regression, or Principal Component Analysis for more advanced datasets.

Correlation does not automatically establish causation. A relationship between variables may be influenced by additional variables or other factors.

Exploratory Data Analysis (EDA)

EDA is the process of examining data before applying formal models or drawing final conclusions. It combines numerical summaries and graphical exploration rather than relying on just one method. Characteristics of EDA:

  • Understand the structure of the dataset
  • Identify missing information
  • Detect unusual observations
  • Explore distributions and discover patterns
  • Investigate relationships and test assumptions
  • Generate questions or hypotheses

Visualisation in EDA

Visualisation helps analysts recognise patterns that are hard to spot from tables alone.

  • Bar chart — categorical variables, e.g. students by programme.
  • Histogram — distribution of a numerical variable, e.g. exam marks.
  • Box plot — median, quartiles, spread and possible outliers.
  • Scatter plot — the relationship between two numerical variables.
  • Line chart — change over time.

Visualisation principles: choose a chart appropriate to the data type, give it a meaningful title, label axes clearly with units, avoid unnecessary decoration, use consistent scales, and avoid misleading or distorted axes.
