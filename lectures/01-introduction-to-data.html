Introduction to Data Exploration

Before exploring or cleaning anything, it helps to be precise about what "data" even means — and about the vocabulary (variables, observations, attributes, data types) you'll reuse in every lecture that follows.

Introduction to data

Data consists of recorded facts, measurements, observations or events that can be stored, processed and analysed — things like a customer's age, a product's price, the number of purchases someone made, transaction dates, images, social-media posts or sensor readings.

Data vs. information

Data is a raw observation or recorded value. Information is data that has been organised, processed or interpreted to provide meaning.

Example

Data: €120, €95, €180, €210, €140

Information: Average customer transaction = €149

Understanding a dataset

Three terms describe the building blocks of any dataset:

  • Observation — one individual entity or instance being studied. One row = one customer, for example.
  • Variable — something that can take different values, e.g. Age, Region, Number of purchases, Spend.
  • Attribute — a characteristic or property describing an entity, e.g. Age and Region are attributes of a customer.

In analytics, the terms variable, feature and attribute are often used in closely related, overlapping ways.

Types of data

Knowing the type of a variable matters because it determines which analytical techniques apply to it.

  • Categorical data — represents groups or labels (Department, Country, Customer type, Product category).
    • Nominal: categories without a natural order — e.g. Dublin, Cork, Galway.
    • Ordinal: categories with a meaningful order — e.g. Low → Medium → High.
  • Numerical data — represents measurable quantities.
    • Discrete: usually countable values — e.g. Number of purchases = 6.
    • Continuous: can take any value within a range — e.g. Revenue = €1,245.75.

Data management

Data management is about how data moves through its lifecycle: it's Collected → Stored → Organised → Maintained → Used → Shared → Archived. Good data management makes data easier to locate, understand, analyse, reproduce, protect and share appropriately.

Important practices include:

  • File organisation — consistent folder structures and meaningful file names.
  • Documentation — data dictionaries, README files and metadata.
  • Data quality — accuracy, completeness, consistency and validity.
  • Data provenance — where the data originated, when it was collected, how it was transformed.
Example

If one system records gender as Male/Female, another uses M/F, and a third uses 1/2, combining the datasets will produce inconsistencies unless these codes are documented and standardised.

Principle: good analysis begins with well-managed and well-understood data.

Primary and secondary data

  • Primary data — collected directly for a particular research or business purpose (surveys, interviews, experiments, customer questionnaires, sensor measurements, observation).
    It's specific to the objective and gives you control over collection and current information — but it's time-consuming, can be expensive, and requires careful design.
  • Secondary data — already collected by another organisation or for another purpose (government open-data portals, CSO datasets, company databases, published reports, research repositories).
    It's usually quicker and cheaper to obtain and can be large-scale — but its quality may be unknown, it may be outdated, and definitions may not match your requirements.

What, where and how of data acquisition

Before acquiring data, an analyst should ask three questions:

  • WHAT data do we need? Start with the business question — e.g. "What factors influence customer churn?" might need: age, contract type, monthly charges, customer service interactions, length of relationship, churn status.
  • WHERE can we obtain it? Internal databases, CSV/Excel files, APIs, open-data portals, surveys, public datasets, sensors, web-based sources.
  • HOW will we acquire it? File download, database query, API request, survey, data collection system, approved web-data collection.
Before collecting any data, consider

Privacy + Ethics + Licensing + Bias + Quality + Security

Version control: Git and GitHub

During an analytics project, datasets, Python files and notebooks change repeatedly. Without version control, files tend to multiply into messes like analysis_final.py, analysis_final2.py, analysis_final_revised.py, analysis_really_final.py. Git provides a systematic alternative.

Core concepts:

  • Repository — the folder containing the project and its version history.
  • Commit — a recorded snapshot of project changes.
  • Push — send local commits to GitHub.
  • Pull — retrieve changes from a remote repository.
  • Branch — a separate development path to work on changes safely.

Why use GitHub for a data analytics project:

  • Tracks project development and provides evidence of work
  • Supports collaboration
  • Protects against accidental loss
  • Improves reproducibility
  • Builds professional practice
