Lecture 3

Exploratory Data Analysis

A closer look at why EDA exists, the numerical and visual toolkit it draws on, and the two frameworks — CRISP-DM and SEMMA — that place EDA inside a complete analytics project rather than treating it as an isolated task.

What EDA is

Exploratory Data Analysis (EDA) is the process of examining and investigating a dataset before formal modelling. It helps us understand the structure, quality and characteristics of the data, and is built on four pillars:

  • Descriptive statistics
  • Data visualisation
  • Data quality checking
  • Identification of patterns and relationships

The purpose is to move from raw data → useful information → informed decisions. EDA is closely tied to data understanding and data preparation — the guiding question throughout is: what is the data telling us, and how can we use that information?

Purpose of EDA

Before analysing or modelling data, EDA helps identify:

  • Missing, incorrect or inconsistent values
  • Duplicate observations
  • Unusual observations or outliers
  • The distribution of variables
  • Relationships between variables
Example questions, student dataset
  • Are enrolments increasing in the courses or not?
  • Which programmes have the most students?
  • Is student satisfaction changing?

CRISP-DM guidance places this exploration of data quality, tables and graphics within the Data Understanding phase.

Data exploration methods

EDA normally combines numerical summaries with visualisation.

Numerical techniques: mean, median, mode, minimum and maximum, standard deviation, frequency counts, correlation.

Visual techniques:

  • Histograms → examine distributions
  • Box plots → identify spread and possible outliers
  • Bar charts → compare categories
  • Scatter plots → investigate relationships
  • Line charts → examine trends over time
  • Pair plots → compare several numerical variables at once

A graph should help answer a question — not just decorate the analysis.

Data quality and preparation

Analysis depends on good-quality data. Common issues: missing values, duplicate records, incorrect data types, inconsistent categories, outliers, invalid values, different measurement formats.

Replacing a missing value isn't neutral — the choice of method should always be justified, since imputing or changing data can affect later analysis. IBM's CRISP-DM documentation flags data assessment and preparation as critical early stages precisely because data quality drives model quality.

# Mean imputation
df["Average_Mark"].fillna(
    df["Average_Mark"].mean()
)

# Median imputation
df["Student_Satisfaction"].fillna(
    df["Student_Satisfaction"].median()
)

# Mode imputation
df["Study_Mode"].fillna(
    df["Study_Mode"].mode()[0]
)

Planning a data science project

EDA should never be performed without a clear objective. A structured project asks:

  1. What is the problem? e.g. understand changes in the dataset.
  2. What data do we need? e.g. year, programme, study mode, enrolment.
  3. Is the data suitable? Check completeness, accuracy, consistency.
  4. What analysis should we perform? Appropriate statistics and visualisations.
  5. How will we validate our findings? Check calculations, assumptions, reproducibility.
  6. How will findings be communicated? Appropriate charts, tables, explanations.

Two frameworks structure this kind of work: CRISP-DM and SEMMA.

CRISP-DM

CRISP-DM = Cross-Industry Standard Process for Data Mining. Six phases:

  1. Business Understanding — define the problem, objectives, success criteria.
  2. Data Understanding — collect, describe, explore and assess the data.
  3. Data Preparation — clean, transform and organise the data.
  4. Modelling — select and apply appropriate analytical/model techniques.
  5. Evaluation — check whether results meet the original objectives.
  6. Deployment — communicate or implement the results.

CRISP-DM is iterative rather than strictly linear — a discovery during modelling, for example, may send you back to data preparation.

Worked example: student performance and enrolment
  • Business Understanding: How are enrolment, performance and satisfaction changing?
  • Data Understanding: Examine Year, Programme, Study Mode, Enrolments, Graduates, Average Mark, Satisfaction.
  • Data Preparation: Handle missing values, duplicates, incorrect data types.
  • Modelling/Analysis: Examine relationships; build statistical or predictive models where appropriate.
  • Evaluation: Check the analysis actually answers the original questions reliably.
  • Deployment: Present findings via report, dashboard or presentation.

SEMMA

SEMMA is associated with the SAS data-mining process:

  • S – Sample: select data that adequately represents the problem.
  • E – Explore: use statistics and visualisations to investigate patterns, trends, anomalies.
  • M – Modify: clean, transform, select and create variables.
  • M – Model: apply appropriate analytical or predictive models.
  • A – Assess: evaluate and compare the results.

SAS documentation places tasks like replacing missing values and transforming variables within the Modify stage specifically.

CRISP-DM vs. SEMMA

Both encourage a structured, iterative process, but their emphasis differs. CRISP-DM explicitly starts from the wider business/problem objective and ends with deployment; SEMMA is centred more directly on preparing, exploring and modelling the data itself.
